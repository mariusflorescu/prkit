# How to check it

A guide says how a person sees the change working by hand: up to five steps, each with what to do and what they should see, and on at least one what to watch for, with an optional setup line and the chapter each step exercises. It is labelled as the agent's suggestion, since the agent read the code and ran nothing. A change with nothing to check by hand (a refactor, docs or tests alone) gets one quiet line with the reason. The reader ticks steps as they go; ticks live in prkit, survive a relaunch, carry into a new revision for every step whose action and expected result read the same and whose chapter's code did not change, and never reach GitHub. Guides written before plans show nothing.

## Sub-features

- `manual-check-card` - the "How to check it" card on the Overview under the summary: the suggestion line, the setup line, numbered steps with "You should see" and "Watch for", each step's chapter number opening its chapter, and the "n of m checked" progress.
- `manual-check-ticks` - a checkbox per step (`Checked step <n>`), saved by the server, kept across a relaunch, carried into the next revision for unchanged steps, unticked for reworded ones, and kept per revision when you switch back.
- `manual-check-code-changed` - a step ticked against code that has since changed (a real edit to a file of the step's chapter) shows unticked with the pill "Code changed since you checked" and the progress title "K changed since you checked"; ticking it again records the new code. A push to another chapter's file, a base merge that only moves lines, and an agent moving an unchanged file into the chapter keep the tick; so does a step with no chapter and a tick stored before ticks kept code. An older revision keeps its own answer.
- `manual-check-nothing` - "Nothing to check by hand." with the agent's reason, and no boxes.
- `manual-check-errors` - a refused save toasts "Couldn't save your tick" and leaves the box as it was; ticks that don't load show "Your ticks didn't load" with Retry and no boxes.
- `manual-check-local` - a local review's Guide page shows the same card and boxes; its ticks live under the local review's own subject and survive a relaunch.
- `manual-check-retention` - a pull request's ticks stay until GitHub says it was merged or closed and no tab shows it, then go with its reviewed files (see [Reviewed files](./reviewed-files.md)); a local review's ticks go when the review is removed.
- `manual-check-outside` - `read_guide` and `read_guide_revision` (`prkit guide read`, `prkit guide revision`) carry the plan, `manualCheckTicked` and `manualCheckChanged` (ticked against code that has changed since, so not ticked); `tick_manual_check_steps` (`prkit guide tick --revision <n> --steps <n>`, `--no-ticked`) sets ticks by step number, records the chapter's code like the checkbox, and an open window follows it at once.
- `manual-check-agent` - real Claude writes concrete steps for the fixture pull request and nothing to check by hand for a refactor (`agent` tag).

## How to get to it (user POV)

- Open a pull request's Guide tab after a guide was written: the card sits under the summary and the before/after, above the author's pre-flight when there is one.
- Open a local review's tab (`prkit local guide` in a repository): the same card under its summary.

## Driving it with e2e

Preconditions: `pnpm build`.

- **Default journey.** `pnpm e2e run tests/manual-check.e2e.ts` reads only the fake GitHub (`startFakeGitHub`, PR 9 behind `outsideGit`), so it needs no fixture lock. The stand-in agent writes the plan `claude.manualCheck(...)` sets. It ticks step 1 (one row in `manual_check_ticks` for the account's subject), opens a step's chapter, relaunches with `--keep-home`, reads and ticks through the CLI (`guide read`, `guide tick`, again with nothing changed, `--no-ticked`, a step that doesn't exist), writes r2 with step 1 reworded only in its caution, step 2 reworded and a new step 3 ("1 of 3 checked"), switches to r1 ("All 2 checked"), refuses a save with a trigger, hides the table across a restart for the read error and Retry, checks the card at 640 wide, and writes r3 with nothing to check by hand. A second test starts a local guide with `prkit local guide`, ticks step 1 on its tab (one row for `local <key>`), relaunches, and removes the review, which removes its ticks. Screenshots `manual-check-*`, light and dark where it matters.
- **Code changed.** `pnpm e2e run tests/manual-check-code-changed.e2e.ts` (fake GitHub only, no fixture lock; PR 9 behind `outsideGit`, `--watch-interval 5000`). The stand-in splits the guide into the chapters "Limits" (`src/limits.ts`) and "Detail" (`src/change-0.ts`) with four steps. It ticks step 1 and 3 in the window and step 2 with `prkit guide tick` (rows in `manual_check_ticks` with `code` naming the chapter's file), inserts a row without code for step 4 while the app is stopped, then pushes with `git.commit` and `fake.gitHead`: a real edit to `src/limits.ts` gives r2 with the pill on step 1 (`aria-describedby`, "3 of 4 checked" titled "1 changed since you checked", `prkit guide read` listing it in `manualCheckChanged`), r1 still reading "All 4 checked", the same states after a relaunch, and a second row for step 1 after ticking it again; an edit to `src/change-0.ts` gives r3 with the pill on step 2 (ticked from the CLI) and none on step 1 or on step 4 (no code); "Generate again" with both files in one chapter (an unchanged-for-step-1 file moved in) keeps step 1 ticked; `git.mergeBase` (a commit on main merged into the branch, checked to move only the hunk's line numbers) keeps it ticked too. Screenshots `manual-check-code-changed-*`, light and dark, and one at 640 wide that checks nothing overflows.
- **Retention.** `tests/reading-state.e2e.ts` (fake GitHub only, no fixture lock) ticks step 1 on PR 9's guide, merges PR 9 and finds `manual_check_ticks` empty within a few ticks, the review `done` and the question and pin still there; its guide then reads `0 of 2 checked`. See [Reviewed files](./reviewed-files.md) for the whole journey.
- **Real Claude.** `PRKIT_E2E_AGENT=1 pnpm e2e run tests/manual-check.e2e.ts --tag agent` runs two guides. The fixture one generates on `<fixture>#1` through the shared instance, so wrap it in the fixture lock; it checks 2 to 5 steps, chapters that are the guide's own, at least one "Watch for", steps that mention the stats or clicks and the rejected URL, and the prompt's `manual-check` section in the log, opens each step's chapter and ticks step 1. The refactor one (`--grep refactor`, fake GitHub, no lock) renames `addLink` and expects nothing to check by hand. Stored guides go to `.e2e/evidence/manual-check/`.

## Gotchas

- The tick follows a step's `action` and `expect`, whitespace aside. A reworded caution or chapter keeps it; any other rewording starts the step unticked. It also follows the code of the step's chapter, compared as the Files tab's "Changed since you reviewed" does: by each file's hunks, only for files in the chapter both then and now. Two steps with the same action and expect are refused by validation.
- The agent journeys spend the Claude subscription, a few minutes each.
