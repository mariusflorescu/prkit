# Website

`apps/www` is prkit's one-page marketing site: an Astro build with no client framework, the brand kit's tokens, favicons and og-image, and Fira Sans and JetBrains Mono served by the site itself. It reads like a paper: one column of text, hairline section rules, and anatomy-kit figures in square frames, with the hero figure breaking out wider. It follows the system color scheme, shows a real screenshot of the guide in light and dark, and plays a short hero intro once per session unless the system asks for reduced motion. It is not deployed anywhere yet.

## Sub-features

- `page` renders the header, the hero, why prkit exists, What it does, the screenshot, How it works, Local first, the facts, FAQ, the download band and the footer from `dist/index.html`. It has five figure slots; a slot shows an empty frame until its drawing lands in `src/figures/<slug>/`.
- `shots` are real screenshots in `apps/www/src/assets/shots/`, captured from a verification instance by `pnpm --filter @prkit/www shots`. The page shows the guide pair.
- `themes` switch every color and screenshot with `prefers-color-scheme`.
- `intro` animates transform and opacity on the first view of a session only, and never under reduced motion.
- `self-hosted` serves every font, image and icon from the site's own origin.
- `figures` are isometric anatomy-kit drawings from `apps/www/src/figures/<slug>/`, inlined at build time by `Figure.astro`, with a `live.js` that loads when the figure comes near view, stops offscreen and stays still under reduced motion. Frames carry a title and a hint, with no figure number, no `Figure n.` caption prefix and no live readout, and nothing in a figure reacts to a pointer moving over it: only its buttons (click, keyboard, arrow keys) and Push's drawn hit area do. Each has a hidden, noindex page at `/figures/<slug>`; `sample` proves the harness, and `pr-guide` is the hero: a pull request window with its file diffs, the agent as a terminal block cursor reading them, and the guide forming behind as app panels whose chapters prkit checks against the diff. Its shared builders live in `kit/prkit-digital.mjs`. The contract is in `apps/www/src/figures/README.md`.
- `client-safe` keeps client names out of shots and the build, and shows every login, name and avatar in the shots as a placeholder (`acme-dev`, `acme-dev/shortlinks`, a generated avatar).

## How to get to it (user POV)

- `pnpm dev:www` and open the URL Astro prints.
- `pnpm build:www`, then `pnpm preview:www`, or serve `apps/www/dist` from any static host.

## Driving it with e2e

Preconditions:

- `pnpm build:www` ran after the last change. The journey serves `apps/www/dist` itself; the `web` target's prkit instance starts but goes unused.

- **Page.** `pnpm e2e run tests/www.e2e.ts`. `heading "Your agents write the code. prkit keeps you in the loop."`, the text `Coming soon` and `link "Follow along on GitHub"` are visible. Scrolling each section and figure heading into view loads the one screenshot, which has alt text, and the page has five `[data-figure]` slots, none with a `[data-corner="fig"]` corner, a `[data-readout]` or a caption starting `Figure n.`. The journey saves `www-hero`. A second journey presses Tab and checks that `Skip to content` has focus and that nothing, the sticky header included, paints over it.
- **Figures.** The same file opens `/figures/sample/`. `meta[name="robots"]` is `noindex, nofollow`, `img "A dial indicator on a surface plate…"` is visible, the caption starts with its sentence, and `[data-figure="sample"]` gets `data-live="on"`. An init script counts `requestAnimationFrame` calls: they climb while the figure is on screen, hold still for 1.5 s once the text `The end of the page` is scrolled into view, and climb again back on the figure. `button "Slide block 3, 10 tall, under the plunger"` gets `aria-pressed="true"` once the carriage arrives. With `matchMedia("(prefers-reduced-motion: reduce)")` replaced to match, no frame is ever requested and the button still moves the carriage. Every figure's reduced-motion journey glides the mouse in small steps over a grid across its drawing and over the parts a pointer once acted on (Push's hit area, the stack layers, the local-first panels), with a `MutationObserver` on the figure, and expects no change at all, not even one reverted on leave. The journey saves `www-figure-sample`. Figures have no readout, so to read a figure's state assert on its buttons' `aria-pressed` and its parts' `opacity`, `visibility`, `style` and `data-tone`. For a figure's look, run its `build.mjs` and the anatomy skill's `capture.mjs` and `lines.mjs` with `--theme light` and `--theme dark`.
- **Hero figure.** The same file opens `/figures/pr-guide/`. `img "A pull request window with its number…"` is visible and `[data-figure="pr-guide"]` gets `data-live="on"`. The tour (about 20 s a loop) starts as the page's intro lands (1.1 s) from the still, on `New commit`, and comes round to `Read`, which the tour presses. Frames hold still after an instant jump to the end of the page. Each step button's name starts with its visible word. `button "New commit: show a new commit starting revision 2"` shows `[data-part="graph-fresh"]`; from there `button "Write: show the agent writing the guide"` presses it within 1 s (the tour can't get there that soon), every file note (`[data-part="file-4-note"]`) shows and no `[data-part$="-pass"]` check shows; ArrowLeft moves focus to `Read` and picks it. Under reduced motion no frame is requested, `New commit` is pressed with two of three checks passed, and `button "Check: show prkit checking each chapter's anchors"` snaps back to revision 1 (no fresh commit, two checks) and presses it. The journey saves `www-figure-pr-guide`. `node apps/www/src/figures/pr-guide/build.mjs --audit` must end `audit passed`.
- **Self-hosted.** Every request the page makes starts with the site's own origin. Fira Sans 400 and 500 and JetBrains Mono 400 are loaded. Astro names each family `<name>-<hash>` and adds metric-matched `fallback` faces; compare names without the hash.
- **Inbox figure.** The same file opens `/figures/inbox-list/`. `img "The prkit window on its Inbox…"` is visible and `[data-figure="inbox-list"]` gets `data-live="on"`. The tour presses `work` first, and frames hold still after an instant jump to the end of the page. While the tour shows every account, `button "client: show only this account's pull requests"` presses it and leaves 3 `[data-row]`s on show; ArrowRight moves focus to `personal` and picks it (2 rows); Escape returns to `All accounts` (9 rows). Under reduced motion no frame is requested, `All accounts` is pressed with 9 rows, and `work` snaps to 4 rows and stays past the tour's quiet spell. The journey saves `www-figure-inbox-list`.
- **Fixes figure.** The same file opens `/figures/fix-commit/`. `img "Fixing review comments, in the order it happens…"` is visible and `[data-figure="fix-commit"]` gets `data-live="on"`. Frames climb on screen and hold still after an instant jump to the end of the page. Back in view, within about 6 s (the journey allows 15) `button "Push: send the commit to GitHub"` gets `aria-disabled="false"` with `[data-part="status-ready"]` and `[data-part="commit-line"]` shown; it stays there without frames and with `status-pushed` hidden until Push, which shows `status-pushed`. Under reduced motion no frame is requested, it rests ready, and Push snaps to `status-pushed` and sets `aria-disabled="true"`. The journey saves `www-figure-fix-commit`.
- **Stack figure.** The same file opens `/figures/stack-guides/`. `img "A stack of 3 pull requests drawn as app windows…"` is visible and `[data-figure="stack-guides"]` gets `data-live="on"`. The tour presses `Layer 1` as it visits the layers, and frames hold still after an instant jump to the end of the page. `button "Layer 3: show its pull request and guide"` presses it and fades the other layers' `[data-lift]` groups; Escape lets it go; ArrowLeft moves focus to `Layer 2` and picks it. `button "Whole stack: on a fresh stack, write a guide for each open layer without one, bottom to top"` hides every `[data-part^="guide-"]` and then, within 15 s, shows all three guides with no cursor typing. Under reduced motion no frame is requested, two guides are written and layer 3's cursor types, a pick stays past the tour's quiet spell, and Whole stack snaps to three written guides. The journey saves `www-figure-stack-guides`.
- **Local-first figure.** The same file opens `/figures/local-only/`. `img "Local first, as a diagram of the software on your Mac…"` is visible and `[data-figure="local-only"]` gets `data-live="on"`. The tour shows one `[data-part^="token-"]` going out to GitHub, and frames hold still after an instant jump to the end of the page. `button "GitHub: show a request carrying your token to GitHub"` presses it and shows one token and one `api-` key; ArrowRight moves to `Your agent`, which lights `[data-part="copy-lit"]` with no token; Escape lets it go. Under reduced motion no frame is requested, nothing is lit at rest, and `button "Disk: search prkit's data folder for a GitHub token"` snaps to the empty search result (`[data-part="empty"]`) and stays. The journey saves `www-figure-local-only`.
- **Intro.** On the first view `html` has no `data-intro`; after a reload in the same tab it is `seen`. Under reduced motion `document.getAnimations()` is empty on the first view too. A local Playwright script records the intro to `.e2e/evidence/www/hero-intro.webm`.
- **Dark.** e2e cannot set the color scheme CSS sees. `emulateOsColorScheme` in `tests/osColorScheme.ts` replaces `matchMedia`, which the app's theme script reads, but the site picks dark in CSS media queries and `<picture>` sources, which it doesn't reach. Capture the page with Playwright's `colorScheme: "dark"` at 1440 and 390 wide.
- **Shots.** `pnpm verify:app start --name www --detach`, then `pnpm --filter @prkit/www shots`. A light and a dark page stay open side by side. A fresh home first asks Claude for the guide on `<fixture>#1` from `.e2e/local.json`, keeping the last light and dark pair before the draft as `progress` and every live pair in `.e2e/evidence/www-shots/live/`, then sends one draft on `src/validate.js` line 6 to the fix agent: two subscription turns, and the fix stays a local commit. A home with a guide keeps the `progress` shots on disk. The stack shot needs an open stack on the fixture that includes #191 (`STACKED` in the script). Each shot prints how many hidden names it checked the page against and fails if any of them is in the page.
- **Client names.** `pnpm --filter @prkit/www check:clients --also <client names>` scans `dist/` against every organization, account and inbox repository the gh accounts on this machine can see, plus the names given. `--also anthropic` must fail, which proves the scan works.
- **Lighthouse.** Run `pnpm dlx lighthouse@13` against `pnpm preview:www`, desktop (`--preset=desktop`) and mobile. Headless Chrome follows the macOS appearance, so pass `--blink-settings=preferredColorScheme=1` in `--chrome-flags` for light, or `0` for dark, and check `final-screenshot` to see which scheme ran. `astro preview` keeps running in the background after it prints its address; `astro preview stop` in `apps/www` ends it.

## Gotchas

- The real gh accounts see client pull requests, and their logins, names and avatars are real people. Never screenshot the app for the site without `apps/www/scripts/clientSafeSocket.ts` in front of the page. It drops every row of another repository wherever it appears (a pull request, a repository, an account's status), and the fixture's journey PRs on `e2e/` branches. It swaps each login, name and avatar for a placeholder and the home path for `~`, and gives the server the real names back. It blocks every request to a host other than the app's own.
- The page sees `acme-dev/shortlinks`, so the script opens `/pr/github.com/acme-dev/shortlinks/<n>`; the socket turns it into the fixture before the server reads it.
- Programmatic `scrollBy` on `[data-pr-scroll]` does not stick; the capture script wheels the mouse instead. The PR header collapses on the first scroll, so it wheels twice.
- Astro's scoped styles do not reach a child component's root element; a class passed to `BrandMark` or `Shot` needs `:global()` in the parent.
- Lighthouse 12 reports `NO_LCP` with Chrome for Testing 153. Lighthouse 13 measures it.
