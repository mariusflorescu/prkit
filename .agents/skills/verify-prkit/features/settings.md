# Settings

Settings is a closeable tab at the end of the title bar's strip, after the PR tabs, with a gear and `Settings`. It has a section list on the left and one route per section under `/settings/<section>`: Accounts, Agents, Guides, Appearance, Keyboard shortcuts and About, with no header row of its own. `/settings` opens the section used last (Accounts the first time); Cmd+, does the same from anywhere and focuses the tab when it is already open. Its ×, Cmd+W while it shows, and a middle click close it, back to the tab it was opened from (the Inbox if that PR is gone). Escape never closes it. The tab, its section and its return tab live in the window's sessionStorage (`prkit.settingsTab`), so a reload keeps them and a relaunch starts without the tab.

## Sub-features

- `settings-open` opens the Settings tab from Cmd+,, the app menu, the palette or a link, on the section used last, or focuses it.
- `settings-tab` is the tab: `link "Settings"` in `navigation "Workspace tabs"` (`[data-settings-tab]`), last in the strip and never reordered, `aria-current="page"` while it shows, with `button "Close Settings"` and the PR tabs' surface, hover and focus. It has no number shortcut; Ctrl+Tab and Cmd+Shift+] reach it as the last tab, and Cmd+Shift+T reopens it when it was the last tab closed. Cmd+Shift+T skips a closed tab that is open again, Settings or a PR, so one press always brings one back.
- `settings-nav` is `navigation "Settings sections"`: six links in order, the current one has `aria-current="page"`.
- `settings-accounts` lists accounts and extra directories with refresh, validation, and recovery: [Settings > Accounts](./settings-accounts.md).
- `settings-agents` lists every agent instance (each kind's default, then the ones added) with its status (`Checking…`, `Off`, `Not found` (Cursor: `Not installed`), `Not signed in`, `Needs attention`, `Unavailable`, `Signed in · <plan>`, `Ready`), the one command that fixes a logged-out instance (with a copy button, `CLAUDE_CONFIG_DIR=… claude auth login` for an instance with its own folder), an on/off switch, Edit in place (label, accent, binary, folder, environment with sensitive values), Remove with a confirm for added instances and Reset to default for defaults, Check again per instance and for all, Add agent (Agent, Name, Setup; Codex can instead sign in with ChatGPT), and the default agent (instance, model and its settings). See [docs/features/agents.md](../../../../docs/features/agents.md). When the user's Codex keeps its login in the keychain, it reads `Codex keeps its login in the keychain. Sign in once for prkit.` with `Sign in for prkit`, and a login prkit holds has `Sign out prkit's login`.
- `settings-guides` turns on automatic guides per account: the server starts a guide with the default agent for each open, non-draft review request on that account, one at a time, never for a PR that already has a review. Inbox rows then show `Guide ready`. More guide settings are added here as one component per subsection.
- `settings-appearance` is System, Light and Dark: [Settings > Appearance](./settings-appearance.md).
- `settings-shortcuts` is the read-only list of the app's shortcuts, rendered from `apps/web/src/features/workspace/shortcuts.ts`, the same table the handler matches against and the title bar's hover hints read.
- `settings-about` is the About prkit section from [Branding](./branding.md).

## How to get to it (user POV)

- Cmd+, (Ctrl+, off macOS), or the macOS menu prkit > Settings….
- Cmd+K, search Settings, choose `button "Settings"`. See [Shell](./shell.md).
- `link "Settings"` in the title bar once the tab is open.
- Open `<url>/settings/<section>` after loading `openUrl`.

## Driving it with e2e

Preconditions:

- Open an isolated instance through `openUrl`.

- **Sections.** `tests/settings.e2e.ts` presses Cmd+,; the path is `/settings/accounts` and `heading "GitHub accounts"` appears. `navigation "Settings sections"` has links `Accounts`, `Agents`, `Guides`, `Appearance`, `Keyboard shortcuts`, `About`. Open another section, press Cmd+W (back at `/`), press Cmd+, again: the path is that section's. `button "Close Settings"` returns to `/` too.
- **Tab.** `tests/settings.e2e.ts` (`Settings is a tab at the end of the strip…`) runs on an instance of its own over the fake GitHub. With PR tabs #1 and #2 open, Cmd+K > `button "Settings"` opens `/settings/accounts`; the strip reads `Inbox, #1, #2, Settings`, `link "Settings"` has `aria-current="page"` and there is no `button "Back"`. It visits every section, and Cmd+, on Agents keeps one Settings tab. Tapping #1 keeps the tab, inactive; Cmd+, comes back to `/settings/agents`. `button "Close Settings"` returns to #1's path, Cmd+, reopens Agents, Cmd+W returns to #1, and Cmd+Shift+T brings Settings back. Closing #2, then Settings, then opening Settings with Cmd+, leaves one Cmd+Shift+T to bring back #2. A reload keeps it showing on Agents with the same strip. Ctrl+Tab goes from Settings to `/` and Ctrl+Shift+Tab back; Cmd+3 opens #2. A reload on #2 keeps the Settings tab inactive, and tapping it opens Agents. With #2 closed, a middle click (an `auxclick` with `button: 1`) closes Settings to `/`. With #1 to #6 open in a 540px window, Cmd+, makes Settings the last tab, fully inside `[data-workspace-tab-viewport]`, with the scroll buttons showing.
- **Escape.** In Agents, open `button /^Agent and model: /`: `combobox "Search models"` has focus. Escape closes the list and the path stays `/settings/agents`; so does Escape in the palette (Cmd+K). A third Escape changes nothing: Settings is a tab, not a dialog. Cmd+W then returns to `/`.

## Gotchas

- The last section is remembered for the life of the window; a reload starts at Accounts again.
- Turning auto mode on starts a guide at once (the switch triggers a check), on the user's subscription.
- The server-info footer belongs to Inbox.
