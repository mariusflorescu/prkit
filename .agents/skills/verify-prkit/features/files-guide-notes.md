# Guide notes on Files

People who skip the guide still get its notes. On the Files tab, the latest accepted guide's line notes sit under their lines and its file notes at the top of their files, each with a quiet `Guide` label, but only where they still apply to GitHub's diff at the head: a line note lands where its row and three rows around it still read the same (`placeNote`), and a file note only while GitHub's change of the file is the one the guide read. Question and risk notes keep `Add as comment`, which makes the same draft the Guide tab would. One toolbar toggle hides or shows them, and the choice survives a relaunch. A few quiet words beside the toggle, in the tab row, say when the guide was written for an older commit, when notes are hidden, when a newer guide is ready, or when the notes couldn't load, with the whole story on hover. They sit first in a row that ends on the right, so nothing they say moves the diffs or the other controls. Notes never move under the reader on their own: the tab keeps the revision it took until the reader asks for the newer one, unless the one it took has nothing for these files, in which case a newer guide comes in the way a first one does.

## Sub-features

- `files-notes` draws placed notes with `[data-guide-note]` labelled `Guide question`, `Guide risk` or `Guide note`, and the file note in `[data-file-diff-note]` after a `Guide` label. The card header counts placed risks and questions. prkit's own "Skipped by your ignore rules" chapter adds nothing to Files.
- `files-notes-toggle` is `button "Hide guide notes"` / `button "Show guide notes"` (pressed when shown), first among the tab row's Files controls, present once the PR has an accepted guide. Hidden notes are not read at all. The choice is stored by the server as `appearance.guideNotesOnFiles` in `settings`; a missing or damaged value reads as shown.
- `files-notes-comment` opens the composer at the note's line on GitHub's diff (`textbox "Comment on line 19"`). The draft carries the note's identity, so `In your review.` shows under the same note on the Guide tab too, and the other way round. A draft whose lines changed since, so it waits below the diff, reads `In your review, on lines that changed since. It waits below the diff.`
- `files-notes-older` reads `Guide notes from an older commit`, titled `Guide notes come from r1, written for an older commit. They show only where the code still reads the same.`, then `3 no longer match and are hidden.`, then `prkit is updating the guide.` while a new revision is being written. A guide with no notes for these files says nothing. On a current guide with notes GitHub's diff can't show: `1 guide note hidden`, titled `1 guide note is hidden: GitHub's diff doesn't show its line now.` In a narrow window the words are cut short before the tab row would scroll.
- `files-notes-newer` keeps the revision the tab took and offers `button "Show newer notes"` (titled with the story, ending `A newer guide is ready.`) once another is accepted; the notes change only once that guide was read, and a failed read toasts `Couldn't load the newer guide's notes` and keeps the old ones.
- `files-notes-writing`: while a new comment, an edit or a reply is open in the PR's diffs, the notes on screen hold still, since the diff keys its inline content by position and a change would lose the words. Hiding says `Guide notes hide after your comment`, showing or a first guide says `Guide notes show after your comment`, and a newer guide says `Newer notes after your comment` (or `Newer notes show after your comment` once asked for).
- `files-notes-states`: the first paint waits for the notes, so they never push a diff down; notes turned on later or a guide landing while Files is open show `Loading guide notes...` in the tab row; a failed read shows `Guide notes unavailable`, titled `Couldn't load the guide's notes.` with the server's words, and `Retry`, and the diffs still render.
- `files-notes-steady`: the list's first file card stays where it is in every painted frame while a guide lands on an open Files tab, a push makes it older, a newer guide is offered and taken, and through the pushes in `thread-push.e2e.ts`.

## How to get to it (user POV)

- Open a PR with an accepted guide and choose `Files`.

## Driving it with e2e

Preconditions:

- `pnpm build` ran after the last change. `tests/files-guide-notes.e2e.ts` and `tests/files-notes-line.e2e.ts` each start their own instance on the fake GitHub with the stand-in Claude (`claude.notes`, `claude.fileNotes`, `claude.hold`) and the local git fixture, so they need no fixture repository and spend no subscription. They serve `fake.files(9, ...)` from `git.patch(9, path)` so Files and the guide read the same change.

- **Placed.** After `Generate guide` writes r1, Files shows three `Guide question` notes and one `Guide risk` under `src/limits.ts`, the file note, `3 questions` and `1 risk` in the header, the toggle pressed, and `1 guide note hidden` for the `src/change-0.ts` note GitHub doesn't list.
- **Comment.** `Add as comment, question on line 3` on Files opens `textbox "Comment on line 3"` with the note's words; Cmd+Enter stores one `pending_comments` row with a `note_key`. The Guide tab's same note reads `In your review.` and carries no `Guide` label.
- **Hide and relaunch.** Tap `Hide guide notes`: no notes, no file note, no words. Stop the instance with `keepHome`, check `SELECT value FROM settings WHERE key = 'appearance.guideNotesOnFiles'` is `false`, start again: still hidden. `Show guide notes` brings them back.
- **Older guide.** Hold the stand-in and push code with four lines above and one noted line changed. Files places the brace question at line 19, keeps the old-side risk, drops the changed line's note and the file note, reads `Guide notes from an older commit` titled with `3 no longer match and are hidden.` and `prkit is updating the guide.`, and the slug note's draft follows its code to line 7 and still reads `In your review.` under the note. Commenting the brace note opens `Comment on line 19`; with new words typed, `Hide guide notes` says the notes hide once the comment is done and leaves the words, and `Show guide notes` takes that back.
- **Newer guide.** Release the stand-in: r2 lands, the notes stay r1's, and the tab row offers `Show newer notes`. Tapping it shows r2's notes (line 14 back) with the file note, and the brace note still reads `In your review.`
- **Steady.** `tests/files-notes-line.e2e.ts`, on the same fake setup, records where the first file card is drawn in every painted frame. At 1280 in light it opens Files with no guide (no toggle), starts a guide and reads Files while it is written, then lets it land, pushes a commit GitHub's diff doesn't show, lets the next guide land while a comment is open and after, and takes it: the card never moves, and the tab row reads nothing, `Guide notes from an older commit`, `Newer notes after your comment` and `Show newer notes` in turn, fitting at 760 wide. At 760 in dark, a guide with no notes for these files says nothing through a push, and the next guide's note comes in without a click. It saves `files-notes-line-no-guide`, `-landed`, `-older`, `-newer-writing` and `-newer` (light and dark, most at 760 too) and the `-none-*-dark` frames.
- **Proof.** `pnpm e2e run tests/files-guide-notes.e2e.ts --output .e2e/proof/<name>` saves `files-notes`, `files-note-composer`, `files-notes-older`, `files-notes-older-moved` and `files-notes-newer` in light and dark, and `files-notes-hidden`.

## Gotchas

- e2e's roles have no `note`; find notes by `[data-guide-note]` and their `aria-label`, under the file's `[data-path]`.
- Wait for a push by the card's stat (`+14 -1`): the diff's lines live in Pierre's shadow root.
- Post `fake.files` before `fake.gitHead`, or the first read of the new head can get the old files.
