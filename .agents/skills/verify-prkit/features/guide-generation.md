# Guide generation

The Guide tab sets a guide up like a document, not a chat: under "No guide yet" and one sentence on what a guide is, a setup block with quiet 12px rows: Agent (the agent and model picker, grouped by provider with the login each uses, then the model's own settings: reasoning effort, fast mode, service tier), Focus (`Add a focus` opens the pull request's own guidance, "What should this guide focus on?"), Settings (one muted line of its guide settings, [guide-config.md](./guide-config.md)), Write for on a stacked PR, and one Generate guide button the size of the PR header's, with Cmd+G in its tooltip. While the agent works, the tab shows one line in the agent's own words, the changed files checked off as the agent's tool calls read them with its one-line note per file, then the draft guide as soon as the agent shares it: Claude's as it writes its one `submit_guide` call, Codex's from `submit_draft` calls with planned chapters faded. The guide becomes a revision only when `submit_guide` passes validation, or `revise_guide` does on top of the call it rejected. Generation keeps running when the user switches PRs: the PR's tab shows a ring that fills with files read and chapters written, its tooltip says "Writing guide · 3/5 files", and a toast plus a macOS notification say "Guide ready". Updates by the watcher are in [review-watcher.md](./review-watcher.md).

## Sub-features

- `guide-setup` starts a guide: agent and model picker and traits picker (rendered from the model's option descriptors) at the `xs` size, the focus behind `Add a focus` (the PR's guidance block, saved to the PR scope when the guide starts and reused by every revision; a PR with saved guidance opens it filled), the settings line, Cmd+G, Cmd+Enter in the focus, or Generate guide. Beside the button, `usually … for PRs this size` shows only from two or more past accepted guides by the same agent instance and model at the same settings on a similar diff, and in its place why Generate can't run. The empty Guide tab, the failed state and the Generate again popover all use this one block; the popover has no empty-state header and no frame of its own.
- `guide-catalog` is `agents.catalog`, one entry per agent instance: Claude's bundled models checked against the installed Claude Code version, Codex's live `model/list` for the signed-in ChatGPT account. A logged-out provider shows its models greyed with the one command that fixes it (`claude auth login`, `codex login`). Check again refreshes it.
- `guide-selection` is stored on the review (instance, its kind, model, options) and shown in the status bar ("Claude Opus 5.5 · High", with "· Work" when another instance of that agent is on). An instance in another conversation group (another config folder for Claude; every Codex instance) starts a new conversation; one in the same group resumes it. A turned-off or removed instance gives way to its kind's default instance, else the default agent, and the setup shows that choice. Generate again reuses it; the chevron next to Generate again opens the guide setup to change it.
- `guide-progress` shows "Claude is reading this PR", `3 of 5 files · 14s · Stop`, a determinate bar, the narration line (`report_progress`), the file list with checks and notes (`note_file`), and Details with the raw tool calls.
- `guide-draft` renders the draft: overview first, chapters as they land. Codex drafts with `submit_draft`, so planned chapters show faded and the progress line reads `Writing chapter 2 of 3`. Claude's draft is its `submit_guide` input read while it streams: each field and chapter appears once it is closed and checks out, the progress line reads `Writing chapter 2` with the bar held at half, chapters show `01` with no total, and the footer says the agent is still writing.
- `guide-default-models` is what runs with nothing saved: the first ready instance's default model at its default settings, Claude Opus 5.5 at Extra High and, when the login lists it with Extra High, Codex GPT-6.1-Sol at Extra High (a login without either keeps Codex's own default). Settings > Agents' default agent, the Guide setup, the inbox row and a fix all start on it, and a saved default, a PR's own agent or a pick wins.
- `guide-timing` times one guide on fixture #1 from the click, by Claude Opus 5.5 at Extra High (the default) or by Codex GPT-6.1-Sol at its default Extra High: first activity line, first narration, first overview, first chapter (and each later one), accepted guide. The first activity line must show within 12 seconds of the click.
- `guide-revise` fixes a rejected `submit_guide` with `revise_guide`: the agent sends only the chapters and fields it changes, prkit applies them to the rejected guide and checks the whole guide the same way.
- `guide-turn-end` ends the agent's turn once `submit_guide` has accepted the guide and the agent has the result, instead of waiting for its closing reply. The revision is still committed only after the process has exited.
- `guide-reads` counts a file read only when a tool call that printed it returned: a Read of the checkout file, or the part of the numbered diff a ranged read printed (Claude's Read offset/limit, `sed -n`, `head`, `cat`, for both agents).
- `guide-context` gives a PR attempt `pull-request-context.json` next to the numbered diff: the failing and pending checks with GitHub's short summary, the unresolved review threads and the issues the PR closes, each part read or unread with the reason. The prompt names the file and its counts and nothing else of it. Watcher, auto-mode and restart attempts read it in the background, so the 10% reserve holds it back and the activity log says so. A new comment or check result starts no attempt.
- `guide-labels` labels shell calls from their parsed program and paths ("Read src/store.js", "Searched for validateUrl in src"); the raw command is only in Details.
- `guide-background` keeps writing on another PR: tab ring and tooltip, a toast "Guide ready · <title> · Open", and a macOS notification whose click focuses the window and opens the Guide tab.
- `guide-entry-points` starts a guide with the default agent from the inbox row's hover action, the command palette ("Generate guide" on a PR) and Cmd+G anywhere on a PR.
- `guide-failed` shows a failure by reason with Retry, and the guide setup to start again with another agent, its focus filled with what was saved.
- `guide-stop`, `guide-restart` and the review lifecycle are unchanged.

## How to get to it (user POV)

- Open a PR from the inbox or its tab, choose `Guide` under `navigation "Pull request tabs"`.
- Hover an inbox row without a guide: `button "Generate guide for <owner>/<repo> #<n>"`.
- `Cmd+K` on a PR, type `generate`: `button /Generate guide/`.
- `Cmd+G` on a PR: the open guide setup's choices, else the default agent, then the Guide tab.

## Gotchas

- A real run spends the user's subscription. Claude journeys need `PRKIT_E2E_AGENT=1`; Codex journeys need `PRKIT_E2E_CODEX=1`.
- After a Claude Code update, Read, Grep or Glob refused with `prkit couldn't check the paths of this <tool> call` means the tool takes a new input field: add it to `READ_TOOLS` in `apps/server/src/agents/claudePermissions.ts` from the SDK's `sdk-tools.d.ts`.
- Tests in one `pnpm e2e run` share an instance, so a later journey finds what an earlier one left. The entry-point journey uses PR #2 because the Claude journey leaves a guide on #1.
- Reading the whole numbered diff checks off every file at once on a small PR. That is the real read; the notes arrive as the agent understands each file.
- The typical time needs two accepted full guides by the same agent instance and model at the same settings (effort, service tier, fast mode) within half to double the diff size; a fresh home never shows it, and a guide from before attempts recorded their settings never counts. The fake's PR pages all report one changed line, so a journey writes its two guides on one-line commits of its own (`git.commit`).
- A rejected `submit_guide` (a file in two chapters, a line note outside a hunk) is fixed with `revise_guide`, about 3 s on fixture #1 instead of 20-30 s for writing it again. A call Claude Code can't parse as JSON never reaches prkit, so it is still written again whole. The draft keeps its last good pieces meanwhile. Duplicates come in bursts: some ten-minute windows have none, others one run in two.
- #447 and its base branch `fixture/blob-prefetch-base` never get pushed to. Only commits GitHub has repacked trip a blob fetch that names the cache's commits, so a fixture pushed minutes ago passes on every build.
- `--rm` homes are deleted on stop even with `--keep-home`; start without `--rm` to keep history.
- The stand-in reports version 2.1.999, so the catalog lists every bundled Claude model. Codex stays the machine's own, and an instance on the fake GitHub has a HOME with no Codex login.
- Base UI wires a `<label for>` into `aria-labelledby`, which beats `aria-label`; the auto-mode switches therefore have no label element.
