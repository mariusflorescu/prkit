# Damaged rows at startup

A stored row prkit can't read, because a newer prkit wrote it or it was damaged, fails alone. prkit starts, the item says what's wrong where the user meets it, and everything else works. A review whose state can't be read stops at a failed guide with Retry, its guide still readable. A fix whose state can't be read is left exactly as it was. A question or a tab that can't be read steps aside for a notice with Remove, a list row steps aside, and the server log says which and why. Nothing is deleted or restarted on the strength of a row prkit couldn't read.

## Sub-features

- `damaged-review` is a pull request's or a local review's `reviews.status` that isn't JSON or isn't a state prkit knows. Startup moves it to `failed(damaged)`: `alert "prkit couldn't read this guide's record"` with Retry above the guide, and `The guide couldn't be updated` in the status bar. Retry writes the guide again, a local review's on its latest run's snapshot. Nothing restarts it by itself.
- `damaged-attempt` is an unfinished attempt prkit can't read. It ends, its agent is left alone, and its review stops the same way.
- `damaged-fix` is a fix turn prkit can't read. It stays as it was (a state that isn't JSON is quoted), and its pull request's Fixes tab says `prkit read a damaged fix record.` While it is unfinished, the fixes queued behind it wait and the checkout stays, even when the session ends, since its agent may still be in it. A session whose own record can't be read keeps its checkout.
- `damaged-question` is a question that doesn't decode. In the Ask dock the review's other questions show, and where the oldest questions are, `status "Questions prkit couldn't read"` says `One question couldn't be read. A newer prkit may have saved it, or the record was damaged.` with Remove, which deletes only questions still damaged. A failed Remove keeps the notice and toasts `Couldn't remove it`.
- `damaged-tab` is an open tab row that doesn't decode. The other tabs open, and after them `status "Open tabs prkit couldn't restore"` says `One open tab couldn't be restored` (or `2 open tabs ...`) with Remove, which deletes only rows still damaged. Remove is announced, so every window drops the notice. A failed Remove keeps the notice under the tab strip's save error with Retry. It stays stored until Remove, or until its pull request is opened again, which replaces it.
- `damaged-agent` is an `agent_instances` row that doesn't decode (`tests/damaged-agent-setting.e2e.ts`). Settings > Agents lists it as its own row, `status "<label> status"` reading `Its setting can't be read` with what to do, and `Remove` (`Reset to default` for a default instance, labelled by its kind); the other agents read as usual. A guide set to use it fails with `Your agent isn't ready` and its words, its attempt recorded on that instance and no stand-in run, so nothing runs on another login. A damaged default never falls back to how prkit ships it, and an instance that is off falls back to it (and fails) rather than past it to the default agent. A row whose kind can't be read either still shows, last, with a neutral icon. Remove (or Reset) deletes only the row; the guide's Retry then runs on the kind's default.
- `damaged-list-row` covers the review feed, the local reviews list, the watcher and the fix feed. Each leaves a row it can't read out and logs `Left out a stored row prkit can't read`.

## How to get to it (user POV)

- Launch prkit after a newer version wrote state this one doesn't know, or after a crash or an edit damaged a row. Then open the pull request, local review, Fixes tab or Ask dock the row belongs to.

## Driving it with e2e

Preconditions:

- `pnpm build` ran after the last change. `tests/startup-damaged-rows.e2e.ts` starts its own instance on the fake GitHub with the stand-in Claude and `outsideGit`, so it needs no fixture repository or lock.

- **Setup.** Outside agents on, a local review from the CLI, guides for #4 and #6 from the Inbox row action, two answered questions on #6, a fix on #9 that ends at once (merged first), a fix on #6 that `claude.hold()` keeps running with a second one queued behind it, a held fix on #2, and a tab for #3.
- **Damage while closed.** `stopFakeInstance(..., { keepHome: true })`, then write the home's `prkit.sqlite` with `node:sqlite`: #4's and the local review's status `garbage`, #6's status a JSON state prkit doesn't know, #9's ended fix status `garbage`, #6's running fix a `failed` state with a reason prkit doesn't know, #2's running fix `work` `not json` (all after `claude.release()`), #2 merged on the fake, the first question's scope `not json`, #3's tab position `first` and #2's `last`, a third question damaged with an empty id, and a damaged pull request tab row under the local review's key.
- **Start.** The instance starts and the Inbox lists every row. On main it doesn't start: the log ends in `SqlError ... malformed JSON` and `server exited (1)`.
- **Each item.** #4 and #6 show the alert with Retry, #6 with its r1 guide, its second question and `2 questions couldn't be read`; #6's Fixes tab shows the damaged fix record and its second fix is still queued; #2's session ends as merged and its checkout stays; #3's, #2's and the local key's rows are gone for `3 open tabs couldn't be restored`, and #6, #9 and the local review are still open; the local page shows the alert, and Retry makes it `Ready`; #4's Retry writes r2; a guide for #1 works.
- **Relaunch.** The damaged rows are stored as they were (the fix turn quoted), #6 is still stopped with no new attempt and its second fix still queued, #2's checkout is still there, the log names each, and opening #3 again stores its tab whole and leaves `2 open tabs couldn't be restored`. With a trigger refusing deletes, each Remove fails and its notice stays; without it, the tab notice's Retry and the question's Remove delete only the damaged rows, and the local review's own tab stays.
- **Agent setting.** `tests/damaged-agent-setting.e2e.ts` (fake GitHub, stand-in Claude): guides on #4 and #6 from the Inbox row, then, while closed, an added `claude_second` row readable but for its `kind` (`garbage`), and #4's review moved onto it. Settings > Agents shows its row with Remove next to working `Claude` and `Codex` rows (light, dark, 640 px). #4's Generate again fails with the claude_second words, its last attempt is on `claude_second` and failed, and `claude.runs()` doesn't grow; #6's Generate again writes r2. `alertdialog "Remove claude_second?"` removes it, and #4's Retry writes r2 on the default Claude. Then, while closed, a damaged `claude` row, a `claude_off` that is off with #4's review on it, and a ready `claude_spare` on its own folder: the `Claude` row reads the same with `Reset to default` and `claude_spare` reads `Signed in`; #4 and #6 both fail with the Claude words, their attempts on `claude`, with no run (planting the old fallback runs #4 on `claude_spare`); after `alertdialog "Reset Claude to default?"` #6's Retry writes r3. On main Settings > Agents reads `Couldn't load agents`.
- **Proof.** `pnpm e2e run tests/startup-damaged-rows.e2e.ts --output .e2e/proof/<name>` saves `damaged-review` in light, dark and at 600 px, `damaged-review-with-guide`, `damaged-question` in light, dark and at 600 px, `damaged-tabs` in light and dark, and `damaged-local-light`.

## Gotchas

- `open_pull_requests.key` is the target of `workspace.active_key`'s foreign key, and `node:sqlite` enforces foreign keys, so damage a tab's position, not its key.
- After a relaunch the app restores the last active tab, not the Inbox; wait for `link "Inbox"` before navigating.
- The local page's header shows the work tree's temporary path; crop it before filing a frame.
