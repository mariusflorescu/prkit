# Fix agent

Review comments and merge conflicts go to a writable agent session per PR (Claude Code or Codex, the same picker as guides). The agent edits a checkout of the branch, prkit commits, and the Fixes tab shows what it did per comment or per file with the diff. Nothing reaches GitHub until Push, unless the repository opts into automatic pushes. A resolution keeps lockfiles, binary and deleted files on the base side for the owner. Push never goes over a branch that moved; it redoes the work on the new head instead.

## Sub-features

- `fix-send` sends drafts or open GitHub threads from Review > Send to agent, or from a draft's or thread's own bot button, with an optional note, the agent instance and model, and replies on GitHub after the push. Picking an instance in another conversation group than the session's says `A different agent starts a new conversation for this pull request.`; one in the same group says nothing and resumes. The Fixes header names the instance when another one of that agent is on.
- `fix-panel` is the Fixes tab, shown once the PR had something sent (a fix or a resolution, running, waiting or ended; `FixerFeedEntry.turns` from the fixer feed). Before that a `tab=fixes` link or a remembered tab opens Conversation, without painting any of Fixes first. The page waits at most 3 seconds for the feed's index, then opens Conversation too, and Fixes appears once the feed says so. It shows the session's agent, the queue newest first, progress with Stop and discard, per-comment or per-file results, the commit's diff, Push, Discard, Ask the agent to change, Copy patch, Retry.
- `fix-conflicts` is the header's Resolve conflicts on a conflicting PR: merge the base (default) or, on your own PR, rebase; the resolution diff compared with each side; needs-human files; Revert resolution after a pushed merge.
- `fix-push` checks GitHub push access, refuses when the branch moved and queues a redo, records a push a crash cut off, and marks fixed drafts resolved-by-agent.
- `fix-settings` is the per-repository Push fixes automatically, Resolve conflicts automatically and Run check scripts on any pull request, under Settings > Guides > For one repository and the Fixes tab's Repository settings.
- `fix-scripts` is whether the agent may run the repository's check scripts on a PR: one quiet line in Review > Send to agent, the Resolve conflicts popover and the Fixes tab's header, with the reason, and on the first turn of a session that may run them, the scripts with their exact commands from the PR head's package.json. Forks and authors who aren't the owner, a member or a collaborator get none unless the repository opts in.
- `fix-watch` ends sessions on merged or closed PRs, drops a pending resolution as Resolved outside prkit, and starts automatic resolutions, at most three a day per PR.
- `fix-restart` reaps an orphaned agent, marks interrupted turns failed with Retry, returns their drafts, and finishes a Stop, Discard or session end a crash cut off.
- `fix-tabs` is the warning dot on a conflicting PR's title-bar tab, the dot on the Fixes tab while the agent works or waits, and the "Fixes ready" toast and macOS notification that open the Fixes tab.

## How to get to it (user POV)

- Open a PR, write drafts on Files, choose Review, then Send to agent.
- Hover a draft or an open thread and click its bot button, "Send the comment on ... to agent".
- On a PR that conflicts with its base, click Resolve conflicts in the header, or in the Fixes tab's banner.
- Open the Fixes tab of a PR that had something sent to the agent.
- Settings > Guides > For one repository, pick the repository, then Fix agent.

- `pnpm build` ran after the last change and the instance passes `pnpm verify:app doctor`.

## Gotchas

- GitHub answers a PR's creation a moment before it serves `refs/pull/<n>/head`, which prkit fetches as soon as the PR opens. Every fixture that opens a PR calls `waitForPullRef` (`tests/reviewFixture.ts`), which logs `Fixture #<n>: GitHub serves refs/pull/<n>/head after <ms> ms` and gives up after 30 seconds with a message that says so.
- GitHub computes `mergeable` after a PR opens or moves, so the header shows Merge until it reads `CONFLICTING`. Poll `pullState` before expecting Resolve conflicts.
- The fixture repository is private, so another account can't read it: the push-denied path is proven by `apps/server/src/fixers/pushAccess.test.ts`, not a journey.
- Claude may try `npm test 2>&1 | tail`; that is allowed. A script chained with `&&` or `;` is refused.
- The fixture PRs are your own, so their scripts always run. The blocked path with a real agent has no journey: no fork PR exists on the fixture repository. `decideScripts`, `decideFixBash` and the Codex approvals are unit-tested instead.
- Auto-push and auto-resolve are per repository and persist in the instance's home: turn them off at the end of a journey that turns them on.
- Never push from a journey to anything but the fixture's own `e2e/fix-*` branches.
- Several fix journeys can share one run's instance: read the fix session of the journey's own PR with `fixerOf(home, number)`, never the first row of `fixers`.
- A fix turn's temp folder is `/Users/Shared/prkit-<6 hex of the turn id>`; none should be left once the turn ends.
